# 第 8 章 EDA、数据库与脚本

本章覆盖设计数据库、工具链分工、脚本工程与 AI 辅助脚本的可信度。使用过的工具与仅了解概念的工具要分开说明。

### Q071 Library Cell View 与技术库是什么

**要点**：设计层次、不同视图与工艺数据有明确绑定关系，显示层、制造层、purpose及参数化器件由相应技术环境控制。核对参考库与tech绑定，不把颜色正确当成层语义正确。跨库迁移要检查数据、器件与配置一致性。

**自测**：换tech后图形仍显示正常，为什么仍可能不能签核？

### Q072 Layout XL 的连接信息有何用途

**要点**：原理图驱动/绑定和connectivity辅助定位器件、端口与网络，提升设计时正确性；不能替代独立LVS和最终数据核对。ECO后检查绑定是否同步、旧对象是否残留。区分本地版本与流程支持，不凭产品名称保证自动迁移成功。

**自测**：原理图改了一个网名，哪些设计状态可能没同步？

### Q073 PV、寄生提取与 EM/IR 工具链应怎样分工

**要点**：介绍工具链时按实际流程说明各类工具解决的问题及自己的输入输出：物理验证（DRC/LVS/ERC/PERC）、寄生提取（PEX/xRC）与 EM/IR 分析各有分工。亲自使用过的工具与仅了解概念的工具分开说明。工具切换时比较输入、模型、单位、覆盖范围、结果差异与资源消耗，不只报速度。

**自测**：新工具跑得更快时，如何证明结果仍可信？

### Q074 描述工具导入与适配经验如何避免空泛

**要点**：说清项目版本与环境、具体故障现象、最小复现步骤、配置问题与工具缺陷的区分、原厂/AE 修复和回归验证。问题统计数字与个人职责要分清：组织跟踪、协调与闭环是一种贡献，不等于亲自修改全部工具底层代码；“首次”类表述限定在真实范围内（如当时的团队/领域），不推广成行业首次。

**自测**：准备一个问题从发现到复验的完整例子。

### Q075 SKILL Python 与 shell 的分工

**要点**：工具内数据库操作采用支持的API/语言，Python适合报告、流程和外部数据，shell/调度串联作业；具体桥接依工具环境。迁移要确认类型、对象模型、坐标与性能，不只翻译语法。批处理输出还需检查完成状态与失败清单。

**自测**：自动打孔和DRC报告统计分别放在哪一层更合理？

### Q076 批量 DRC 修改如何保证安全

**要点**：确认报错规则与共性结构，预览候选对象，限定修改范围，备份并先小样本运行。改后检查几何、连接、寄生与相关规则；日志保留未处理/失败项。不能按坐标盲改或因为报错数少了就停止。

**自测**：一个规则修改影响到匹配单元时还需怎样验收？

### Q077 自动打 pin 与 via 最易漏什么

**要点**：pin检查名字、层/purpose、端口与几何连通；via检查层对、包围、合法孔型、栅格及导通能力。重复运行、旋转镜像和边界输入都要覆盖。不能默认所有工艺使用同一矩形孔或单孔模板。

**自测**：提出一例脚本不崩溃但生成错误数据的情况。

### Q078 PCell CDF 与模型为何一起核对

**要点**：PCell生成几何，CDF/属性影响参数与网表，器件模型解释电学；参数命名与总宽约定可能不同。修改几何或批量属性后，对照生成、抽取与参考网表。自制PCell不仅要DRC合法，还要pin、模型和边界参数可信。

**自测**：版图画出来但LVS类型错，可能在哪一环失配？

### Q079 Linux vim 版本管理与归档怎样体现工程能力

**要点**：能准确查看/编辑配置、搜索日志、处理权限与作业、核对版本及建立可复现归档。说明真正做过的提取/归档脚本输入、输出、失败处理和回归；不要把“会vim”当作脚本开发证明。工具、规则和数据快照应共同归档。

**自测**：如何保证另一同事能复现你本次LVS或PEX？

### Q080 AI 生成脚本怎样进入设计流程

**要点**：把AI用于候选逻辑、解析和文档辅助，人工核对API/参数与设计意图，再在只读或测试库中验证。类型、单位、权限、循环性能和输出验收不可省略。输入只使用可用于该环境的数据；不以可运行代替正确性，也不宣称AI已解决所有模拟约束。

**自测**：列出脚本从候选到正式使用的四道检查。
